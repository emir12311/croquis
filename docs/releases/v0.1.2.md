Offline circuit simulator: build an Arduino circuit on a canvas, write a sketch, and run
it on a real AVR core. No server, no account, no network.

- **AppImage** — recommended. One file, no root, works on any distribution. Adds itself
  to your application menu on first launch.
- **.deb** — `sudo apt install ./Croquis_*.deb`
- **.rpm** — `sudo dnf install ./Croquis-*.rpm`
- **Arch, Artix, Endeavour** — `packaging/arch/PKGBUILD` in the source, `makepkg -si`

Every package carries its own AVR toolchain, so compiling a sketch needs nothing else
installed. AGPL-3.0.

## Fixed in 0.1.2

- **Snapping works on a first-launch canvas** — a part dropped on a fresh breadboard now
  lands in a hole. Palette pin offsets and board holes are measured on demand instead of
  waiting for the asynchronous thumbnail pass.
- **No more random snapping** — a part only moves when *every* leg can sit in a hole.
  Seating a single leg used to pull an LED to an unrelated hole.
- **The world origin is no longer a wall** — snapping no longer clamps to positive
  coordinates, so a board placed at the centre (negative coordinates) behaves like any
  other board.
- **The canvas redraws when its layout changes** — resizing the window, opening the
  serial monitor or collapsing a panel no longer stretches the old bitmap until you
  click or move something.
- **Undo after saving is safe** — undo/redo marks the circuit dirty again, so File → New
  warns before discarding it.
- **Failed saves and opens are visible** — shown in the circuit panel instead of being
  logged only to the console.
- **Cancelled gestures stay cancelled** — a cancelled press no longer starts or finishes
  a wire, drops a part, or clears the selection.
- **Paste is one undo step.**
- **The webview enforces offline** — a no-network CSP, and the file commands accept only
  absolute `.json` paths (8 MiB cap).

### Under the hood

- `App.svelte` is split into document, project, file, view, sketch, sim, canvas and input
  modules, each with its own tests.
- Release CI now checks the tag against every manifest and runs `svelte-check`, the
  frontend tests and the engine tests before packaging.
