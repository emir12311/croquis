Offline circuit simulator: build an Arduino circuit on a canvas, write a sketch, and run
it on a real AVR core. No server, no account, no network.

- **AppImage** — recommended. One file, no root, works on any distribution. Adds itself
  to your application menu on first launch.
- **.deb** — `sudo apt install ./Croquis_*.deb`
- **.rpm** — `sudo dnf install ./Croquis-*.rpm`
- **Arch, Artix, Endeavour** — `packaging/arch/PKGBUILD` in the source, `makepkg -si`

Every package carries its own AVR toolchain, so compiling a sketch needs nothing else
installed. AGPL-3.0.

## Added in 0.1.3

- **Compiler errors point at the line** — `avr-g++` diagnostics are listed with their
  line and column in the serial panel. Click one and the Sketch panel opens with the
  caret on that line; notes and warnings keep their severity.
- **The serial monitor can send** — a docked input row feeds `Serial.read()` in the
  running sketch, with an optional trailing newline. The engine now has a UART input
  path, and an engine test proves a sent byte is read back.
- **Closing with unsaved work asks first** — **Save and close**, **Discard and close**
  or **Cancel**, instead of quietly losing the circuit or sketch.
- **Pull requests run the suites** — type-check, frontend tests and engine tests run on
  every PR, with the toolchain cached. Releases already ran them.

## Fixed in 0.1.3

- **Restart keeps analogue and digital inputs** — a fresh simulator now receives the
  potentiometer voltage or held button level again even when it has not changed. The
  duplicate-suppression caches used to survive the restart, so `analogRead()` could
  stay at 0 after **Restart**.

### Under the hood

- Compiler output is parsed by a pure, tested module; only `sketch.ino` diagnostics are
  jumpable, so a header or linker error is shown but not turned into a bad caret move.
- `Sim.sendSerial` is gated to a running desktop simulation; the browser build still
  solves the netlist and keeps the input disabled.
