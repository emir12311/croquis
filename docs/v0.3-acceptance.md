# v0.3 acceptance

> **The goal, in one sentence:**
> *I want to be able to do everything I can do in v0.2 on here.*

That is the whole target. The criteria below are only a way to check it. If something
is possible in v0.2 and missing from the egui app, v0.3 is not done.

This is the concrete definition of “finished v0.3”. It is deliberately smaller than
“port every idea from the plan”. If a feature is not listed here, it is not required
for v0.3.0.

## v0.3.0 is done when

1. **One native binary.** The shipped app is Rust + egui. It does not start a
   webview, load JavaScript, or depend on Tauri/Svelte/node at runtime.
2. **Same files.** Every v0.2 `diagram.json` and every shipped preset opens, edits,
   saves and round-trips without data loss.
3. **Same circuits.** Every v0.2 part in the catalogue is present, wired, and
   electrically behaves the same as v0.2 for the preset corpus.
4. **Same loop.** A user can open a preset, edit the sketch, press Run, see compile
   errors or serial output, watch the circuit state change, and press Stop.
5. **Same editor fundamentals.** Syntax highlighting, line numbers, selection,
   undo/redo, clipboard, find, diagnostics with jump-to-line, and tab indentation.
6. **Same interactions.** Palette, drag/drop, grid snapping, breadboard seating,
   orthogonal wiring, bend points, selection/marquee, move/rotate/copy/paste,
   properties, warnings, undo/redo, zoom/pan, fit view.
7. **Same parts, live.** LEDs, RGB, sensors, displays, relay, servo, stepper,
   keypad, shift register and protocol parts update from the netlist/simulator.
8. **Same audio.** Buzzer audio works and stops with the circuit.
9. **Installed.** `.deb`, `.rpm` and AppImage install and pass the end-to-end check
   on a clean machine, including a sketch compile against the bundled toolchain.
10. **Proven.** The old-vs-new differential corpus passes, `cargo test` and the
    native UI tests pass, and the owner has used the installed app for a real
    session.

Until all ten are true, v0.2 remains the stable app and the egui app stays on the
v0.3 branch.

## Out of scope for v0.3.0

- multiple boards or multiple sketches at once
- a browser/WASM build
- new parts or presets beyond v0.2 parity
- cloud/accounts/telemetry
- redesigning the visual language

## Milestones, in order

### A. Blink, end to end (current)

The first vertical slice, using the existing spike:

- open Blink
- edit the sketch
- compile with `croquis-sim`
- Run/Stop
- show compile errors
- show serial output
- drive the LED from the simulated pin
- save the document

No new panels, adapters or visual experiments until A works.

### B. Preset/catalogue parity

- preset chooser
- open/save/new
- all parts placed/wired/saved
- netlist parity on the preset corpus
- differential old-vs-new harness

### C. Rendering parity

- RGB, segment displays, LED bar and servo state adapters
- differential native-vs-Wokwi rendering checks
- breadboard and 74HC595 native drawings

### D. Shell and editor polish

- menus, properties, diagnostics, completions, line numbers
- themes, shortcuts, warnings, audio

### E. Packaging and cutover

- installed package tests
- release notes
- remove the old frontend only after the acceptance list passes

## Rule for this branch

If a request does not move milestone A to done, it waits, unless it fixes a defect in
A. This is what prevents another half-finished shell.
