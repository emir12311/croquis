# v0.2 — The common starter kit

**Status: groundwork.** The part list and behaviour model below are the plan; the
only code landed with this document is the tested PWM timing primitive in
`src-tauri/src/timing.rs`. No new part is shipped yet.

## The target

A learner should be able to follow the common starter-kit lessons offline, not just
the first three chapters. The reference inventories are:

- **Elegoo Super Starter Kit** — 24 lessons: LEDs, buttons, pot, active/passive
  buzzer, tilt, photoresistor, thermistor, RGB LED, 1- and 4-digit 7-segment,
  LCD1602, SG90 servo, stepper + ULN2003, ultrasonic, DHT11, joystick, IR
  receiver/remote, relay, DC motor, 74HC595, transistors and diodes.
  <https://courses.ideate.cmu.edu/16-223/f2023/text/resources/Elegoo-kit.html>
- **Arduino Starter Kit** — 15 projects: LEDs, phototransistor, TMP36, tilt, LCD,
  DC motor, servo, piezo, H-bridge, transistors, capacitors, diodes.
  <https://store.arduino.cc/products/arduino-starter-kit>

The drawing surface is already covered for most of these by `@wokwi/elements`
1.9.2; the work is the electrical/behavioural model, not the artwork. Tags and pin
names below are from that package and Wokwi's supported-hardware list:
<https://mintlify.wiki/wokwi/wokwi-docs/supported-hardware>.

### Tier C — later, not v0.2

NeoPixel (WS2812 timing), OLED/SSD1306 (I2C), RTC/SD (I2C/SPI), MPU6050,
RFID, TFT, and the 37-in-1 long tail. A **generic analog sensor** and a **generic
digital sensor** with a label and a slider/toggle can cover many long-tail modules
without inventing a model for each one; decide later.

## The foundation this slice lays

1. **PWM timing.** A pin's level alone cannot dim an LED, set RGB, run a motor or
   measure a servo pulse. `src-tauri/src/timing.rs` now turns a stream of
   `(cycle, high)` edges into `duty_per_mille`, `high_cycles` and `period_cycles`,
   with tests for 50% PWM, 25% PWM, servo pulses and slow buttons. The next slice
   calls it from `pin_notify` and emits a `PinTiming` event on a 20 ms tick.
2. **Render state.** `RenderState` gains `pinTimings` and per-part state; the
   renderer's `partKey` stops branching on `inst.kind` for each new part and reads
   the state the part kind declares.
3. **Catalogue entries.** Each part gets a `PartDef` (tag, attrs, `pinNode`, fields)
   and a behaviour entry: what it consumes (pin levels/duty) and what it produces
   (LED state, drive, analog voltage).
4. **Netlist.** Analog sensors append to `analogs`; digital sensors append to
   `drives`; output parts read `pinTimings`. The existing potentiometer is the
   template for a wired, validated analog source.
5. **Offline libraries (v0.3).** Add a bundled `libraries/` include path to the
   compiler, with Servo as the proof. No network, no user-installed packages;
   every bundled library gets a `NOTICE` entry.
6. **Presets and tests.** Every lesson slice ships a `presets/*.json` and a test:
   netlist state, a compile/run test where it reaches the engine, and a drive check
   for the visible result.

## Rules

- **A part is not real until it can be wired, driven, seen and tested.** Catalogue
  art alone is not a feature.
- **Behavioural models, not a circuit solver.** A photoresistor is a voltage source
  with a slider; a relay is a switch; a servo is a pulse-width reader. Do not grow
  an arbitrary SPICE model.
- **Offline.** Libraries ship in the package; no runtime downloads.
- **Presets are the lesson.** Every new part gets at least one preset that starts
  from the palette and ends in a visible result.
- **No silent parts.** An unwired sensor, a missing rail or an impossible value is
  reported the way the potentiometer already reports a floating end.

## Risks

- **Wokwi attribute names and pin geometry** differ per element; verify each
  element's `pinInfo` and properties before wiring it. The renderer rasterises the
  element, so the pin map is the source of truth.
- **PWM event volume.** Emit one timing event per pin per 20 ms, not one per edge.
- **7-segment multiplexing** needs the display to remember digits between scans;
  do not solve it by reading the pins only at frame boundaries.
- **Libraries and licensing.** Bundling a library changes the package size and the
  `NOTICE`; test the packaged build, not just the dev build.
- **Free-agent delegation** can produce plausible parts with weak docs/tests; the
  review gate in `AGENTS.md` still applies.
