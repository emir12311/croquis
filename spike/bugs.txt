Croquis (egui spike) — what is actually left
============================================

Audited 2026-11-10 against the working tree at 06cfcd6, by running the suite
rather than by reading the old list. Every line below is either proved by a
test that exists and passes, or is real work that nobody has started.

The previous version of this file listed 15 bugs. Thirteen of them were already
fixed and tested when it was last read, which is why it felt endless: it was a
list of finished work.


Still open — real work, not bugs
--------------------------------

1. No language system.
   The UI's strings are hard-coded English in `spike/egui/src/main.rs`, and the
   part and field labels come from `crates/croquis-core/src/catalogue.rs` as
   `&'static str`. Needs a design decision: where the strings live, and whether
   the catalogue keeps its English labels as the canonical keys or grows a
   per-locale shape. No test covers this, because there is nothing to cover yet.

2. The code editor's QoL is poor.
   Multiline edit, syntax colouring, completion and diagnostic jumps all work
   (see Spike B), but there is no bracket matching, no auto-indent, no comment
   toggle and no grouped undo. Judgement call, not a defect: it needs a
   decision about which of those are worth having before it needs code.

Good to know
------------

`cargo test --manifest-path spike/egui/Cargo.toml` runs 114 tests headlessly in
about a second, with no display. If a behaviour is worth keeping, it is worth a
test here: a hand-test that only exists in your head is what turns one bug into
an evening.
